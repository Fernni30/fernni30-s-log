
## 1. 개요

> 시스템 보안을 개선하기 위한 일련의 절차로, 본질은 **위험(Risk)을 식별하는 것**입니다.



---

## 2. 4단계 절차

| 단계          | 내용                                    |
| ----------- | ------------------------------------- |
| 1. 보호 대상 식별 | 어떤 시스템·애플리케이션을 보호해야 하고, 어떤 역할을 하는지 파악 |
| 2. 취약점 평가   | 취약점·약점이 무엇이고, 어떻게 악용될 수 있는지 분석        |
| 3. 대응 계획 수립 | 확인된 취약점으로부터 보호할 행동 계획 작성              |
| 4. 재발 방지 정책 | 같은 취약점이 다시 생기지 않도록 정책 도입              |


---

## 3. 의의

- 조직의 **IT 자산**(소프트웨어·하드웨어)에 대한 **상위 수준의 개요**를 만들어 줌
- 취약점 해결 절차까지 함께 정리되어 **시스템 위험을 줄임**

---

## 4. UKC와의 관계

> UKC는 공격자가 어떤 순서로 어디를 뚫고 들어오는지 보여주는 지도입니다. 그 지도를 보면 "우리 시스템에서 어디가 위험한지"를 찾기 쉬워지고, 그게 곧 위협 모델링입니다.


> 예시

| UKC 단계      | 우리 조직에 던지는 질문                  |
| ----------- | ------------------------------ |
| 정찰          | 인터넷에 직원 이메일·서버 정보가 얼마나 노출돼 있지? |
| 전달          | 피싱 메일이 직원에게 도달하는 걸 막을 수 있나?    |
| 익스플로잇       | 패치 안 된 서비스가 있나?                |
| 권한 상승·내부 이동 | 한 PC가 뚫리면 다른 서버까지 갈 수 있나?      |
| 목표 실행       | 중요 데이터가 보호돼 있나?                |

이렇게 따져보면 "여기가 약하니 공격자가 이 경로로 올 수 있겠구나"가 보이고, 거기에 맞춰 대응 계획을 세우게 됩니다.

| 프레임워크      | 용도 (참고)     |
