## 1. Attacking Systems Directly (시스템 직접 공격) 정리

> **"문지기가 아무리 뛰어나도, 자물쇠가 허술하면 소용없다"**

시스템 자체의 취약점을 직접 공격하는 방식

### ㄱ. Human 공격 vs System 공격

| 항목            | Human 공격         | System 직접 공격             |
| --------------- | ------------------ | ---------------------------- |
| **방법**        | 심리 조작, 사기    | 기술적 취약점 익스플로잇     |
| **피해자 인지** | 속아서 돕거나 모름 | 완전히 모름                  |
| **피해 범위**   | 개인 단위          | 시스템 전체 (대규모)         |
| **방어 수단**   | 교육, 인식 훈련    | 패치, 보안 설정, 취약점 관리 |

---

## 2. How Systems Are Attacked (시스템 공격 방법) 정리

### ㄱ. 공격 유형

| 항목            | Human-Led           | Vulnerabilities | Supply Chain              |
| --------------- | ------------------- | --------------- | ------------------------- |
| **시작점**      | 사용자 실수         | 소프트웨어 결함 | 신뢰된 소프트웨어         |
| **탐지 난이도** | 낮음                | 중간            | **매우 높음**             |
| **피해 규모**   | 개인~소규모         | 중간~대규모     | **대규모**                |
| **방어 방법**   | 교육, 패스워드 정책 | 패치 관리       | 소프트웨어 검증, 모니터링 |

> SOC 분석가 관점

```
Human-Led    →  패스워드 정책 강화 + 보안 교육으로 예방
Vulnerability →  주기적 패치 관리 + 취약점 스캐닝
Supply Chain  →  이상 행동 모니터링 + 신속한 사고 대응 필수
```

## 3. Software Vulnerabilities (소프트웨어 취약점) 정리

> "모든 소프트웨어에는 결함이 있다. 문제는 누가 먼저 발견하느냐이다."

### ㄱ. 🕳️ Zero-Day (제로데이)

- 공격자가 **방어자보다 먼저** 취약점을 발견한 상태
- 패치가 존재하지 않아 방어가 극히 어려움
- **SOC의 탐지 능력**이 유일한 방어선

### ㄴ. 📋 CVE (Common Vulnerabilities and Exposures)

- 취약점이 공개되면 부여되는 **공식 식별 번호**
- 예: `CVE-2014-6271` (Shellshock)
- CVE 공개 순간부터 **공격자 vs 방어자의 레이스** 시작

> SOC 분석가 관점

```
CVE 공개 전 (Zero-Day)
  → 이상 행동 모니터링으로 조기 탐지가 유일한 방어

CVE 공개 후
  → 패치 적용 전까지 임시 조치 + 익스플로잇 시도 모니터링

패치 적용 후
  → 패치 미적용 시스템 없는지 확인
```

## 4. Misconfigurations (잘못된 설정) 정리

> "버그가 아니라 사람의 실수 — 편의를 위해 보안을 희생한 결과"

| 구분          | Vulnerability          | Misconfiguration  |
| ------------- | ---------------------- | ----------------- |
| **원인**      | 소프트웨어 자체의 결함 | IT팀의 설정 실수  |
| **해결책**    | 패치(업데이트)         | 올바른 재설정     |
| **발생 이유** | 개발 과정의 버그       | 편의성 추구, 실수 |

### ㄱ. 대응 방법

> SOC 분석가의 일반적 역할

- 대부분 **공격자가 익스플로잇한 후에** 발견
- 사후 탐지 및 조사

| 방법                     | 설명                                                          |
| ------------------------ | ------------------------------------------------------------- |
| **Penetration Testing**  | 윤리적 해커를 고용해 실제 공격을 시뮬레이션 → 취약점 보고     |
| **Vulnerability Scans**  | 도구를 주기적으로 실행 → 기본 패스워드·구버전 소프트웨어 탐지 |
| **Configuration Audits** | CIS Benchmark 같은 모범 사례와 비교해 수동으로 시스템 검토    |

### ㄴ. 요약

> Misconfiguration의 주요 원인

→ 편의성 추구 (짧은 패스워드, 기본 설정 유지)
→ IT팀의 실수 또는 지식 부족
→ 보안보다 운영 효율 우선

예방 3단계

1. Pen Test → 실제 공격처럼 테스트
2. Vuln Scan → 자동으로 약점 탐지
3. Config Audit → 기준과 비교해 수동 검토
